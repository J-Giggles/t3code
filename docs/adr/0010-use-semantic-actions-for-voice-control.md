# Use semantic product actions for voice control

Command State resolves speech into a shared Voice Action Catalog whose entries define stable product actions, parameters, spoken aliases, availability, and risk classification. Visual controls and voice invoke the same actions. Command Vocabulary maps a preferred phrase to one action, while Voice Routines compose cataloged actions, stop on failure, inherit the highest risk, and use one aggregate confirmation when consequential. Theo may propose Command Suggestions from repeated behavior, but explicit acceptance is required before any executable mapping is created. Model-driven UI manipulation may assist diagnostics but is not a product contract, and uncataloged actions are reported as unsupported rather than guessed. A Voice Parity Gate requires each new interactive capability to ship with a tested action or an explicit reviewed exception. This requires explicit action seams but makes voice behavior testable, predictable under UI redesigns, and capable of enforcing confirmation policy centrally.
