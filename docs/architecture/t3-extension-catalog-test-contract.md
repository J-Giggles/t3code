# T3 Extension Catalog Test Contract

Status: accepted baseline from 2026-07-14; revised exclusive-autonomy S6 amendment awaiting explicit acceptance

Every accepted platform feature has three deterministic unit cases: normal (`-N`), refusal or failure (`-F`), and durable or safety invariant (`-I`). These unit tests are mandatory in addition to integration, fault, headed, replay, supply-chain, performance, accessibility, migration, and live-tailnet evidence.

## Broader Evidence Required

- Property tests for graph resolution, capability version selection, lock determinism, manifest cutover, permission monotonicity, and migration ordering.
- Fault injection for artifact corruption, process crashes/hangs, interrupted installs, migration failure, activation failure, drain timeout, failed live proof, and failed recovery proof.
- Supply-chain checks for reproducible builds, immutable tags, workflow identity, attestations, signatures, licenses, and source-to-artifact digest binding.
- Headed web and Electron checks for the Extension Manager, permission/activation plans, provenance disclosure, visual evidence, dashboard, and public-tailnet journeys.
- Mobile checks for every converted mobile contribution and `vp run lint:mobile` when native code changes.
- Clean-upstream compatibility runs for exact commits and every declared supported adapter/capability version.
- Existing per-topic matrices: 165 accepted topic features and 495 stable unit cases across the 19 registered topics plus On-the-Go remain mandatory and are rendered in the hosted per-topic plans.
- Repository gates: `vp check`, `vp run typecheck`, applicable `vp test` or `vp run test`, topic/catalog validators, and strict live public-route verification.
