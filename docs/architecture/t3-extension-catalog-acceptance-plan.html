01

The amended decision

Current repository policy already overrides ADR 0044's earlier no-human-approval language. Proposed ADR 0064 makes the architecture truthful and durable.

Autonomy stops at durable Staging

Nightly and Staging may assemble, activate, and verify the exact candidate. The durable terminal state is awaiting-main-approval, never promoted.

Approval binds evidence, not a moving branch

Approval names the held record, revision, artifact vector, Public Base Lock, Private Overlay Lock, Combined Assembly Digest, and both lane proofs.

Main is one Linux/Mac transaction

After approval only, both durable hosts are drained, snapshotted, prepared, activated, relaunched, and live-verified as one coordinated operation.

Rollback restores both hosts

If either host fails after activation starts, both snapshots return and the previous Known-Good Assembly is verified live on both.

02

Promotion state machine

The approval boundary is a real persisted state, not a prompt inside a running command. No Main-side preparation happens on its left.

03

Implementation slices in this amendment

These are narrow S6 components in the public extensions monorepo and T3 adapter. They remain package-owned so they can be reattached after upstream T3 Code changes.

A · Protected activation receipts

Remove every artifact-owned path from an exact checkout, reinstall the immutable closure, run frozen install, focused behavior, and launcher proof from that activated tree, then independently verify all receipt digests.

B · Complete product drain lifecycle

Track orchestration/SQLite transactions, provider turns through processed terminal events, ingestion, migrations, streams, reactors, deletion, checkpoints, and registered background work under inherited admission authority.

C · Persistent exact approval hold

Persist the held Staging record and approval receipt across restart. Resume from held proofs without re-resolution or re-staging. Refuse stale, replayed, missing, or tampered approval.

D · Durable two-host adapter

Require one Linux primary and one distinct Mac launcher host. Prepare both before activating either; preserve both snapshots until both live proofs accept the same Known-Good Assembly.

Privacy boundary: helper commands, launcher output, artifact locations, and operational logs stay in mode-0600 protected evidence outside the public ledger. Public evidence carries only safe receipts and digests.

Acceptance and stop conditions

Accepting this revision supersedes ADR 0044's no-approval rule and narrows ADR 0060 through proposed ADR 0064.
No draft remediation is committed as accepted implementation until this exact hosted checksum is approved.
After acceptance, the extension worktree must pass its complete checks, typecheck, tests, build, and two-axis review before durable staging.
Main still requires a later fresh approval of the exact verified Staging revision, its evidence, and expected downtime.
Durable promotion uses clean worktrees, backup refs and snapshots, no re-resolution, and one coordinated Linux/Mac transaction.
Completion requires live public proof on both hosts plus verified rollback evidence for every exercised failure path.
Decision requested: explicitly accept this hosted revision to authorize completing and committing the S6 remediation. This acceptance does not itself authorize any future Staging-to-Main move.
